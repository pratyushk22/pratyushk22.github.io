Lecture 12 · Reinforcement Learning

Nobody tells you the right answer

Only whether things are going well. Everything in this lecture is the consequence of that one missing label.

MDPs · Bellman · value & policy iteration · continuous states · fitted value iteration

Up to now every algorithm we built had a teacher. There was a \(y^{(i)}\) sitting next to every \(x^{(i)}\), and the whole job was to make the model's output agree with it. Supervised learning is, at bottom, imitation.

Now suppose I've built a four-legged robot and I want it to walk. What is the correct label for "leg joint angle at time t"? I have no idea. I know what walking looks like, but I can't write down the right action at every instant. Explicit supervision isn't just expensive here — it doesn't exist.

So we downgrade what we ask for. Instead of a right answer at every step, we ask for a single scalar: a reward that says this was good or this was bad. Moving forward, positive. Falling over, very negative. That's it. The algorithm has to work out the actions on its own.

why this is hard The reward is delayed and aggregated. The robot falls at step 200 because of something it did at step 40 — but the signal arrives 160 steps late, attached to the wrong action. Credit assignment is the whole problem.

1The MDP: the formal object

The formalism is a tuple \((S, A, \{P_{sa}\}, \gamma, R)\):

  • \(S\) — states. For a helicopter, every position and orientation it can be in.
  • \(A\) — actions. What the control sticks can do.
  • \(P_{sa}\) — state-action transition probabilities. For each state \(s\) and action \(a\), a distribution over where you land next. This is where the world's randomness lives.
  • \(\gamma \in [0,1)\) — the discount factor.
  • \(R : S \to \mathbb{R}\) — the reward function.

The process just runs: you're in \(s_0\), you pick \(a_0\), the world rolls a die and puts you in \(s_1 \sim P_{s_0 a_0}\), you pick \(a_1\), and so on.

\[ s_0 \xrightarrow{\ a_0\ } s_1 \xrightarrow{\ a_1\ } s_2 \xrightarrow{\ a_2\ } \cdots \]

The total payoff is the discounted sum

\[ R(s_0) + \gamma R(s_1) + \gamma^2 R(s_2) + \cdots \]

and the goal is to maximise its expectation. The expectation matters: the transitions are stochastic, so the same policy gives different trajectories on different runs, and the only sensible thing to optimise is the average.

what \(\gamma\) is really doing Two jobs at once. Practically it makes the infinite sum converge — \(R\) is bounded, so the series is dominated by a geometric one. Conceptually it's an interest rate: a reward today beats the same reward tomorrow, so the agent is pushed to collect good things early and postpone bad things.

2Policy, value function, Bellman

A policy is a function \(\pi : S \to A\). No memory, no time index — just a lookup from state to action. Executing \(\pi\) means always taking \(a = \pi(s)\) when you're in \(s\).

The value function of a policy is the expected payoff if you start at \(s\) and follow \(\pi\) forever:

\[ V^\pi(s) = \mathbb{E}\!\left[ R(s_0) + \gamma R(s_1) + \gamma^2 R(s_2) + \cdots \ \middle|\ s_0 = s,\ \pi \right] \]

Now the move that makes everything computable. Peel off the first term:

\[ V^\pi(s) = \underbrace{R(s)}_{\text{now}} + \underbrace{\gamma \sum_{s' \in S} P_{s\pi(s)}(s')\, V^\pi(s')}_{\text{everything after}} \]

That's the Bellman equation, and it's just the discounted sum re-read as immediate reward + discounted value of wherever I land. The second term is \(\gamma\,\mathbb{E}_{s' \sim P_{s\pi(s)}}[V^\pi(s')]\) — the average value over the distribution of next states.

The payoff is computational. For finite \(|S|\), this is one linear equation per state — \(|S|\) equations in \(|S|\) unknowns. Write them down, solve the system, done. An infinite-horizon expectation collapses into linear algebra.

The optimal version

\[ V^*(s) = \max_\pi V^\pi(s), \qquad V^*(s) = R(s) + \max_{a \in A} \gamma \sum_{s'} P_{sa}(s')V^*(s') \]

Same structure, except we no longer let a fixed \(\pi\) choose the action — we take the best one. And the optimal policy just reads off the argmax:

\[ \pi^*(s) = \arg\max_{a \in A} \sum_{s'} P_{sa}(s')\,V^*(s') \]

The fact I find genuinely surprising: \(V^*(s) = V^{\pi^*}(s) \geq V^\pi(s)\) for every \(s\) and every \(\pi\). One single policy is simultaneously optimal from every starting state. There is no "if I start here, strategy A is better, but if I start there, strategy B is" — the same \(\pi^*\) dominates everywhere.

why one policy suffices Because \(V^*\) is defined per-state and \(\pi^*\) is defined by a per-state argmax. The choice at \(s\) only ever depends on \(s\) and on \(V^*\), never on how you arrived. That's the Markov property doing its work — the state is a sufficient statistic for the future.

3Value iteration and policy iteration

Value iteration is the Bellman optimality equation used as an assignment instead of an equation:

  1. Set \(V(s) := 0\) for all \(s\).
  2. Repeat until convergence: \(\;V(s) := R(s) + \max_a \gamma \sum_{s'} P_{sa}(s') V(s')\).

You can do the sweep synchronously (compute all new values, then overwrite) or asynchronously (update in place, one state at a time). Both converge to \(V^*\).

Policy iteration alternates instead:

  1. Initialise \(\pi\) randomly.
  2. Repeat: (a) compute \(V := V^\pi\) by solving the linear system; (b) set \(\pi(s) := \arg\max_a \sum_{s'} P_{sa}(s')V(s')\).

Step (b) is called making \(\pi\) greedy with respect to \(V\). The two steps chase each other: evaluate the policy exactly, then improve it against that evaluation.

The tradeoff is exactly the one in my notes: policy iteration converges in remarkably few iterations, but each one requires inverting a system of size \(|S|\). Blow up the state space and that becomes intolerable, so value iteration wins in practice.

why value iteration converges The Bellman backup is a \(\gamma\)-contraction in the sup norm: \(\|BV_1 - BV_2\|_\infty \le \gamma \|V_1 - V_2\|_\infty\). Banach gives a unique fixed point and geometric convergence to it. The discount factor isn't just a modelling choice — it's what makes the operator a contraction at all.

4When you don't know \(P_{sa}\)

Everything above assumed we know the transition probabilities and the reward. Usually we don't. But we can run trials and count:

\[ P_{sa}(s') = \frac{\#\{\text{took } a \text{ in } s \text{ and landed in } s'\}}{\#\{\text{took } a \text{ in } s\}} \]

which is the maximum likelihood estimate. If the ratio is \(0/0\) — we've never tried \(a\) in \(s\) — we fall back to \(1/|S|\), the uniform distribution. Same trick as Laplace smoothing: a uniform prior wearing a different hat.

The question I kept circling Why keep the numerator and denominator counts around separately, instead of just storing the probabilities?

Because counts are the sufficient statistic and probabilities aren't. New experience arrives as a single increment: num[s,a,s'] += 1, den[s,a] += 1. Cheap, exact, and order-independent.

If instead you stored the normalised distribution, then to fold in one new observation you'd have to un-normalise, add, and re-normalise across the whole row of \(|S|\) entries — and you'd have destroyed the information about how much evidence you had. A row that says \((0.5, 0.5)\) is a completely different epistemic state depending on whether it came from 2 samples or 2000. The counts remember; the probabilities forget. So you accumulate counts continuously and divide only when you actually need \(P_{sa}\), which is periodic and comparatively expensive.

5Continuous states: the wall

Everything so far assumed a finite table of states. A car has state \((x, y, \theta, \dot x, \dot y, \dot\theta) \in \mathbb{R}^6\). The inverted pendulum from PS4 has \((x, \theta, \dot x, \dot\theta)\). A helicopter has twelve dimensions. There is no table.

Option 1: discretize

Chop \(\mathbb{R}^d\) into a grid, treat each cell as a discrete state, run value iteration. Simple, and it genuinely works — but it fails in two distinct ways.

Bad representation. A grid forces \(V\) to be piecewise constant. Consider a dataset that a straight line fits perfectly; a piecewise-constant fit on the same data is a staircase. No smoothing within a cell, no generalisation across cells. To approximate a smooth function you need absurdly fine cells.

Curse of dimensionality. Discretize each of \(d\) dimensions into \(k\) values and you get \(k^d\) states. With \(d = 10\) and \(k = 100\) that's \(10^{20}\) — not representable on any machine. Rule of thumb: discretization is excellent in 1D and 2D, workable up to about 4D with care, occasionally 6D if you're clever and lucky, and hopeless above that.

Option 2: approximate \(V^*\) directly

Instead of chopping up the state space, parametrise the value function:

\[ V(s) = \theta^T \phi(s) \]

Now \(V\) is stored in a handful of numbers rather than a table indexed by state. Generalisation comes for free — nearby states get nearby values because \(\phi\) is smooth.

6Needing a simulator

To do this we need to sample next-states, which means a model: a black box taking \((s_t, a_t)\) and returning \(s_{t+1} \sim P_{s_t a_t}\).

Two ways to get one. Write the physics — for the inverted pendulum you know the pole's mass and length, so you can compute the next state directly. Or learn it from trials, which is just supervised learning again. Fit

\[ s_{t+1} = A s_t + B a_t \]

by least squares over all recorded transitions:

\[ \arg\min_{A,B} \sum_{i=1}^{n} \sum_{t=0}^{T-1} \left\| s^{(i)}_{t+1} - \left( A s^{(i)}_t + B a^{(i)}_t \right) \right\|_2^2 \]

which is the MLE under Gaussian noise. Keep it deterministic and \(s_{t+1}\) is fully determined; make it stochastic by adding \(\epsilon_t \sim \mathcal{N}(0,\Sigma)\). Nothing forces linearity — \(s_{t+1} = A\phi_s(s_t) + B\phi_a(a_t)\), or locally weighted regression, work the same way.

notice the recursion We've turned an RL problem into a supervised-learning problem twice over: once to learn the dynamics, once to fit the value function. RL isn't a replacement for supervised learning so much as a scaffolding built out of it.

7Fitted value iteration

Now the assembly. In the continuous case the Bellman update is

\[ V(s) := R(s) + \gamma \max_a \int_{s'} P_{sa}(s') V(s')\,ds' = R(s) + \gamma \max_a \mathbb{E}_{s' \sim P_{sa}}[V(s')] \]

Two things are impossible here: we can't do this for every \(s\), and we can't evaluate the integral. Fitted value iteration approximates both.

  1. Sample \(n\) states \(s^{(1)}, \ldots, s^{(n)}\) at random. Set \(\theta := 0\).
  2. Repeat:
    • For each \(i\), and each action \(a\): sample \(s'_1, \ldots, s'_k \sim P_{s^{(i)}a}\) from the simulator and set \(q(a) = \frac{1}{k}\sum_{j=1}^{k}\left[ R(s^{(i)}) + \gamma V(s'_j) \right]\).
    • Set \(y^{(i)} = \max_a q(a)\).
    • Set \(\theta := \arg\min_\theta \frac{1}{2}\sum_{i=1}^n \left( \theta^T\phi(s^{(i)}) - y^{(i)} \right)^2\).
The whole trick is in the last line. Discrete value iteration writes \(V(s^{(i)}) := y^{(i)}\) into a table. Here we can't, so we do the next best thing — treat \(\{(s^{(i)}, y^{(i)})\}\) as a supervised training set and regress \(V\) onto it.

So \(s\) plays the role of \(x\), the Bellman target \(y^{(i)}\) plays the role of \(y\), and any regression algorithm slots in. The \(k\) samples are there only to Monte-Carlo the expectation; with a deterministic simulator you set \(k = 1\) and it's exact.

Acting is the same machinery once more:

\[ \arg\max_a \mathbb{E}_{s' \sim P_{sa}}[V(s')] \;\approx\; \arg\max_a V(f(s,a)) \]

where the approximation pushes the expectation inside \(V\) — \(\mathbb{E}[V(s')] \approx V(\mathbb{E}[s'])\) — and ignores the noise. Fine when \(\epsilon_t\) is small, and it saves you \(k|A|\) simulator calls per decision.

The honest caveat Fitted value iteration has no convergence proof. Discrete value iteration converges because the Bellman backup is a \(\gamma\)-contraction. Here we compose that backup with a regression step, and the projection onto the span of \(\phi\) can expand distances. Contraction \(\circ\) expansion is not a contraction, so the fixed-point argument dies. In practice it usually converges anyway.

That's the shape of the whole lecture, really. Every guarantee we had in the tabular case — exact Bellman solves, contraction, convergence to \(V^*\) — was bought with the assumption that we could enumerate the states. Give that up and you keep the algorithm but lose the theorem.
